# Иерархия делегирования

Из коробки три агента с разными ролями:

```
   Пользователь
        │
 ┌──────┼──────────┐
 Ассистент   Сисадмин   Скрайбер
 (универсал,  (интерфейс  (узкий
  хаб)         управления) специалист)
     │
     └─ делегирует специализированным агентам (по мере появления)
```

## Роли

- **Ассистент** — главный рабочий агент (ресёрч, код, сайты, презы, документы). Хаб делегации: раздаёт задачи специализированным агентам, когда они есть.
- **Сисадмин** — интерфейс управления системой. Не рабочий и не в цепочке делегации — он создаёт/настраивает агентов и чинит систему.
- **Скрайбер** — пример узкоспециализированного агента (только транскрибация).

## Правила делегации

- Делегировать можно только агентам из своего `can_delegate_to` (agents.toml). В чужого — bridge молча отбросит.
- **Скрайберу делегируют редко:** транскрибацию пользователь обычно шлёт прямо в топик 🎙. Ассистент делегирует ему только если транскрипция всплыла внутри большей задачи.
- Сисадмину не делегируют — он управляет, а не выполняет рабочие задачи.

## Как растить систему

Пользователь через Сисадмина создаёт новых узких агентов (по паттерну Скрайбера). При создании Сисадмин предлагает настроить делегацию — обычно добавить нового агента в `can_delegate_to` Ассистента, чтобы тот мог раздавать ему задачи.

Подробности механики — `knowledge/system/delegation.md`.
