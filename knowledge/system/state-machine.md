# State machine — состояния агента

Мост хранит для каждого агента состояние (файл `.state` в папке агента).

## Состояния

| Состояние | Что значит |
|---|---|
| `IDLE` | Свободен, ждёт сообщений |
| `ACTIVE` | Сессия открыта, недавно отвечал |
| `BUSY` | Прямо сейчас выполняет запрос (новые сообщения копятся в очередь) |
| `WAITING` | Делегировал задачу и ждёт результата (idle-таймер выключен) |

## Сессия и контекст

- Первое сообщение → **cold start**: агент читает CLAUDE.md + context.md.
- Дальше мост держит сессию (через `--resume`), агент помнит диалог.
- Контекст растёт → каждый turn дороже.

## Daily reset

Раз в сутки (время в .env: `DAILY_RESET_HOUR` / `DAILY_RESET_MINUTE`):
1. `context.md` → снэпшот в `context_archive/YYYY-MM-DD.md`
2. Сессия сбрасывается → агент начинает день с чистого контекста
3. WAITING-агенты не трогаются

Смысл: за день контекст разрастается (200K+ токенов). Сброс = fresh start, но `context.md` (важное) сохраняется.

## Auto-compact

Если агент долго работал без сброса (idle >60 мин) — мост компактизирует сессию (уменьшает контекст). Поле `real_turns_since_compact` защищает от повторного compact.

## Keep-alive (для WAITING)

Если агент в WAITING (ждёт делегацию):
- Мост пингует его каждые 30–55 мин, чтобы кэш провайдера не умер (TTL ~1 час).
- Пинг = «дай короткий статус» → ответ идёт в TG, пользователь видит прогресс.

## Сброс вручную

Команда `/new` в топике агента (с подтверждением) → следующее сообщение = cold start.

## Диагностика

`/state` в топике агента → показывает состояние, session_id, число turn'ов, last_activity, waiting_for.
