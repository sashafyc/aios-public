# Архитектура системы

## Из чего состоит

```
Telegram-группа с топиками
        │  (поллинг)
   ┌────▼─────┐
   │  bridge  │  tg_bridge.py — оркестратор
   └────┬─────┘
        │ роутит по (chat_id, topic_id)
   ┌────┼────────┬─────────┐
 Ассистент   Сисадмин   Скрайбер   ← агенты (каждый = папка + CLAUDE.md)
        │
   runner (claude/codex/deepseek/gemini CLI или API)
```

## Мост (bridge/)

Один процесс `tg_bridge.py`. Что делает:
- **Поллит** Telegram (getUpdates) по каждому уникальному bot token.
- **Роутит** сообщение по `(chat_id, topic_id)` → находит агента в `agents.toml`.
- **Запускает** runner агента (CLI-сессия), стримит ответ обратно в топик.
- **Очередь** на агента: пока агент BUSY, сообщения копятся и склеиваются.
- **State machine**: помнит состояние каждого агента между сообщениями.
- **Делегация**: парсит теги `[DELEGATE:X]` → передаёт задачу агенту X. Глубина ограничена (`MAX_DELEGATION_DEPTH`, по умолчанию 3) — дальше стоп, чтобы не было бесконечных цепочек.
- **Maintenance loop** (фон): hot-reload конфига, daily reset, keep-alive, обработка cron-очереди, чистка протухших approval'ов (TTL).
- **Стартовый анонс**: при запуске мост шлёт в топик Сисадмина приветствие (один раз) + self-check (`doctor`) — что подключено, что нет.
- **Restart-resume**: тег `[RESTART]` гасит мост корректно и после рестарта **восстанавливает сессию** агента, который его инициировал (Сисадмин не теряет контекст того, что чинил).
- **Баг-репорты**: нетривиальные (UNKNOWN) ошибки раннера ловятся и пишутся локально; отправка анонимна и по умолчанию включена (см. ниже).

## Агент

Папка `agents/<name>/`:
- `CLAUDE.md` — роль и инструкции (читается при каждом старте сессии)
- `context.md` — память между сессиями
- `journal.md` — уроки/история
- `AGENTS.md`, `GEMINI.md` — симлинки на CLAUDE.md (для Codex/Gemini)

Агент = промпт + рабочая папка + runner. Мост держит для него сессию.

## Routing: один бот — много агентов

В `agents.toml` все агенты могут иметь один `bot_token_env = "BOT_TOKEN"`. Мост:
1. Группирует агентов по токену.
2. На каждый уникальный токен — один поллер.
3. Поллер ловит сообщения из всех топиков → по topic_id определяет агента.

Хочешь отдельного бота с аватаркой — заведи второй токен в @BotFather, укажи другой `bot_token_env`.

## Конфигурация

- `bridge/agents.toml` — агенты (hot-reload каждые 60 сек, рестарт не нужен). Это твой личный файл (gitignored); из репо приезжает только `agents.toml.example`, из него установщик создаёт живой `agents.toml`.
- `bridge/.env` — секреты (токены, API-ключи). Правка → нужен рестарт. Шаблон — `.env.example`.
- `bridge/settings.json` — permissions для Claude в нативной схеме (`permissions.deny` / `permissions.ask` с паттернами вроде `Bash(rm -rf:*)`, `Read(.env)`). `settings-sysadmin.json` — мягче (Сисадмин управляет ключами). Deny-правила работают даже в bypass-режиме.

Живые файлы агента (`CLAUDE.md`, `context.md`, `journal.md`) тоже твои и не в репо — установщик создаёт их из `*.example` / `*_template`.

## Обслуживание и обновление

- **Единый манифест расписания** — `scripts/crontab` (один файл на весь проект: watchdog, doctor, cleanup, проверка обновлений, задачи агентов). `scripts/cron-sync.sh` применяет его в управляемый блок crontab. Агенты **не плодят свои кроны** — только дописывают строки в манифест и коммитят.
- **Обновление** — `scripts/update.sh` (ежедневная проверка). Модель **hard/soft**: Сисадмин обновляет ядро по релизам безопасно (бэкап → ff-pull → ресабстит путей → тесты → откат при провале → рестарт), **не затирая** твои настройки/агентов/инструкции. После обновления Сисадмин шлёт changelog. Подробности — `update.md`, `upgrade-notes.md`.

## Баг-репорты и приватность

Local-first: баги всегда пишутся в `logs/bugs/bugs.jsonl` (секреты замаскированы, пути → `~`). Анонимная отправка разработчику **включена по умолчанию** (`AIOS_BUGREPORT=1`), легко выключается. Уходит только техническая мета (версия, ОС, тип ошибки, обрезанный стектрейс), без файлов/переписки/ключей. Полностью — `bug-reports.md` и `PRIVACY.md`.
