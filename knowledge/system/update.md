# Обновление системы — безопасный апдейт до новой версии

Система ставится через `git clone`, поэтому новые версии приходят через `git pull`.
Делать это руками опасно: можно затереть настройки, кастомных агентов и правки
инструкций. Поэтому есть один безопасный скрипт — `scripts/update.sh`.

## TL;DR

```bash
bash $AIOS_ROOT/scripts/update.sh --check   # есть ли обнова (ничего не меняет)
bash $AIOS_ROOT/scripts/update.sh --yes     # обновиться без вопросов
bash $AIOS_ROOT/scripts/update.sh           # обновиться с подтверждением
```

`--check` → exit 0. Если обнова есть — выведет версию и changelog. Если нет —
напишет «уже последняя версия».

## Что делает update.sh (по шагам)

1. **`git fetch`** и сравнение локальной версии с `origin/main`. Нет разницы →
   «уже последняя версия», выход.
2. **Changelog** — содержимое `CHANGELOG.md` (если есть) либо `git log` между
   старой и новой версией.
3. **Бэкап** в `$AIOS_ROOT/.backups/<timestamp>/`:
   - `bridge/.env`, `bridge/agents.toml`, `bridge/settings.json`,
     `bridge/settings-sysadmin.json` — копией;
   - вся папка `agents/` (кастомные агенты + правки инструкций);
   - `PREV_COMMIT` — коммит до обновления (точка отката).
4. **`git stash`** локальных правок отслеживаемых файлов — чтобы `git pull`
   прошёл fast-forward без конфликтов.
5. **`git pull --ff-only`**. При расхождении истории — НЕ ломает: оставляет код
   как был, правки в stash, выходит с ошибкой и понятным сообщением.
6. **Возврат правок** (`git stash pop`) поверх нового кода. Если по
   отслеживаемым файлам (`settings*.json` / правки `CLAUDE.md`) конфликт —
   предупреждает и оставляет эталонные копии в бэкапе, ничего не затирая молча.
   (`agents.toml` gitignored — в этом шаге не участвует и конфликтовать не может.)
7. **Подстановка `__AIOS_ROOT__`** в `settings*.json` (как делает install.sh) —
   если в новых файлах вернулся плейсхолдер.
8. **Тесты** `pytest tests/`. Упали → автоматический откат к старой версии +
   восстановление конфигов из бэкапа, выход с ошибкой.
9. **Рестарт моста** (systemd `aios-bridge` на Linux / launchd на Mac).
10. **Итог**: старая версия → новая, путь к бэкапу.

## Что сохраняется (НЕ затирается)

| Что | Как защищено |
|---|---|
| `bridge/.env` (секреты) | gitignored (pull не трогает) + бэкап копией |
| `bridge/agents.toml` (конфиг агентов, кастомные агенты) | **gitignored** — pull его НЕ трогает, сохраняется как есть + бэкап копией. В репо только `agents.toml.example`. |
| Кастомные агенты (`agents/<свой>/`) | untracked → pull не трогает + бэкап папки `agents/` |
| Правки инструкций (`agents/*/CLAUDE.md`, `context.md`, `journal.md`) | отслеживаются git → stash + бэкап; при конфликте предупреждение, не молча |
| `settings.json` / `settings-sysadmin.json` | бэкап + повторная подстановка `__AIOS_ROOT__` |

## Как откатиться вручную

Каждый бэкап лежит в `$AIOS_ROOT/.backups/<timestamp>/` и содержит `PREV_COMMIT`.

```bash
cd $AIOS_ROOT
git reset --hard "$(cat .backups/<timestamp>/PREV_COMMIT)"
cp -p .backups/<timestamp>/.env              bridge/.env
cp -p .backups/<timestamp>/agents.toml       bridge/agents.toml
cp -p .backups/<timestamp>/settings*.json    bridge/
bash scripts/enable.sh   # или рестарт моста вручную
```

(При провале тестов скрипт делает это сам автоматически.)

## Частые проблемы

| Симптом | Что значит / что делать |
|---|---|
| «Не удалось обновиться fast-forward» | В отслеживаемые файлы вносили правки, разошлась история. Код НЕ изменён. Правки в stash (`git stash list` → `aios-update-...`). Реши конфликт вручную или восстанови из бэкапа. |
| «Конфликт при возврате правок» | После pull твои правки конфликтуют с новой версией файла. Эталонные копии — в `.backups/<ts>/`. Слей вручную или возьми нужную версию. |
| «Тесты упали» | Скрипт сам откатился к старой версии. Система работает на прежней версии. Сообщи о проблеме (баг новой версии). |
| «не git-репозиторий» | Систему ставили распаковкой архива, не через clone. Обновление через git недоступно — переустанови через install.sh, сохранив `.env`/`agents.toml`. |
| «Нет прав sudo для рестарта» | Linux без sudoers-правила. Выполни `sudo systemctl restart aios-bridge` вручную (или `bash scripts/enable.sh`). |

## Расписание

Проверка обновлений уже стоит в едином расписании (`scripts/crontab`, **ежедневно
в 09:00**): `update.sh --check` при наличии новой версии шлёт уведомление в топик
Сисадмина (один раз на версию, без спама). Изменить частоту — правка `scripts/crontab`
+ `cron-sync.sh` (см. `cron.md`).
