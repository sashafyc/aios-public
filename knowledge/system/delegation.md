# Делегация — агенты передают задачи друг другу

## Как работает

Агент пишет тег `[DELEGATE:<agent>]` → мост передаёт задачу указанному агенту, тот выполняет и возвращает `[RESULT:...]`. Пользователь видит весь pipeline в TG.

## Теги

| Тег | Что делает |
|---|---|
| `[DELEGATE:<agent>[:task-id]]` | Передать задачу агенту |
| `[RESULT:<agent>:<task-id>]` | Вернуть результат инициатору |
| `[WAITING_FOR:<agent>[:task-id]]` | Уйти в WAITING (ждать результат, idle-таймер выкл) |

## Правила

1. Делегировать можно только агентам из списка `can_delegate_to` в agents.toml. Делегация в чужого — мост молча отбросит.
2. После делегации агент пишет `[WAITING_FOR:...]` — иначе через 60 мин compact потеряет контекст.
3. `RESULT` адресный: `[RESULT:assistant:task-42]`.

## Настройка делегации X → Y

В `agents.toml` у агента X:
```toml
[agents.assistant]
can_delegate_to = ["scriber", "researcher"]
```
Hot-reload подхватит. Теперь Ассистент может делегировать Скрайберу и Ресёрчеру.

## Что видит пользователь

```
💬 Ассистент: "Нужна транскрибация, делегирую Скрайберу."
🎙 Скрайбер:  📥 Получил задачу [task-001], выполняю
🎙 Скрайбер:  [результат]
🎙 Скрайбер:  ✅ Задачу [task-001] завершил
💬 Ассистент: 📤 Получен результат [task-001]
💬 Ассистент: "Вот транскрипция: ..."
```

Служебные сообщения (📥 ✅ 📤) мост отправляет сам.

## Иерархия из коробки

- Ассистент → Скрайбер
- Сисадмин — не делегирует (делает сам через tools)
- Скрайбер — выполняет, возвращает результат

Добавляешь агента через Сисадмина — он предложит настроить делегацию.
